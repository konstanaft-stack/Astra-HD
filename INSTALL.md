# Установка экспериментальных r30 native-base и Center05

> **Экспериментальный R30 / Center05.** NewGame и mirror-редактор проверены в обычной R30 через OpenXR SIM в Test3 и VR Night City: персонаж и UI видны в обоих глазах. **В обоих профилях после выхода из редактора монитор показывает мир, а изображения обоих глаз в composed-выводе остаются чёрными. Это известное неисправленное ограничение R30; причина ещё не установлена.** Полный профильный проход, физическая HMD-приёмка R30, стабильная генерация кадров и целевой FPS не подтверждены. Принятый пользователем HMD-результат относится к mirror-редактору R29 / Test3.
>
> Два согласованных runtime-архива и их SHA256 приведены ниже. [Предыдущий r29 / Center04](https://github.com/konstanaft-stack/Astra-HD/releases/tag/astra-hd-r29-experimental-20261018) не содержит NewGame-исправление R30 и остаётся с известным чёрным экраном при создании персонажа.

Нужны собственная Steam Cyberpunk 2077 **2.31**, Windows x64, подходящий драйвер для выбранных NVIDIA-библиотек, настроенный OpenXR runtime шлема и **[PowerShell 7 (`pwsh`)](https://learn.microsoft.com/powershell/scripting/install/installing-powershell-on-windows)** в PATH. .NET SDK для готового VR-центра не нужен: runtime включён. Другие версии игры и GPU-конфигурации не объявляются проверенными.

Скачайте с [одной страницы выпуска](https://github.com/konstanaft-stack/Astra-HD/releases/tag/astra-hd-r30-experimental-20261019):

- [Astra-HD-r30-native-base-20261019-experimental.zip](https://github.com/konstanaft-stack/Astra-HD/releases/download/astra-hd-r30-experimental-20261019/Astra-HD-r30-native-base-20261019-experimental.zip)
- [VR-CENTR-public-win-x64-20261019-experimental05.zip](https://github.com/konstanaft-stack/Astra-HD/releases/download/astra-hd-r30-experimental-20261019/VR-CENTR-public-win-x64-20261019-experimental05.zip)
- [SHA256SUMS.txt](https://github.com/konstanaft-stack/Astra-HD/releases/download/astra-hd-r30-experimental-20261019/SHA256SUMS.txt)

Суммы можно проверить в PowerShell:

```powershell
Get-FileHash .\Astra-HD-r30-native-base-20261019-experimental.zip -Algorithm SHA256
Get-FileHash .\VR-CENTR-public-win-x64-20261019-experimental05.zip -Algorithm SHA256
```

## 1. Распаковать две отдельные папки

Создайте папку **Astra-HD-R30** и извлеките в неё native-base ZIP: у него файлы лежат непосредственно в корне архива. ZIP центра уже содержит папку **VR-CENTR**. После распаковки структура должна выглядеть так:

```text
AstraVR/
├─ Astra-HD-R30/
│  ├─ bundle.json
│  ├─ stock-paths.json
│  ├─ Install-Selected.ps1
│  ├─ files/
│  └─ licenses/
└─ VR-CENTR/
   ├─ Start-VR-CENTR.cmd
   ├─ VRPorts.exe
   └─ ...остальные файлы центра...
```

Не копируйте содержимое native ZIP вручную поверх игры. `files/` — хранилище объектов для installer, а не дерево игровых папок. Не переносите готовый частный `config.json` с другого компьютера.

## 2. Сохранить чистую основу ДО установки VR

Для нового чистого профиля нужна действительно чистая игра. Запустите её без модов до первого главного меню и выйдите. Это создаёт начальные настройки и служебное пользовательское состояние. Игровой прогресс, сохранения и свои коллекции переносите отдельной резервной копией; они не входят в публичные архивы.

Запустите из распакованной папки центра:

```powershell
.\Start-VR-CENTR.cmd
```

Wrapper обнаружит обычную Steam-папку или спросит **`Full path to your Steam Cyberpunk 2077 directory`**. Если игра находится, например, в другой Steam library, укажите её фактическую папку с `bin\x64\Cyberpunk2077.exe`. Пробелы поддерживаются.

На запрос **`Full path to your separately obtained Cyberpunk VR bundle`** укажите полную папку **Astra-HD-R30**, в которой лежат `bundle.json` и `stock-paths.json`. Это путь к распакованной папке, не к ZIP. У wrapper нет отдельного параметра `-BundleDirectory`.

В центре нажмите **«Сохранить чистую основу»** и подтвердите фактический первый запуск и выход. Если отображается блокировка первого запуска, завершите её штатным подтверждением после выхода из игры. **Native Apply не создаёт чистый снимок автоматически.** Изменённая игра, отсутствие оригинальных файлов или уже существующий прогресс могут привести к отказу проверки. Не обходите такой отказ удалением библиотек или сохранений: сохраните свои данные и сообщение об ошибке для разбора.

## 3. Создать Flat и отдельный VR-профиль

1. При закрытой игре через **«+»** создайте чистый профиль, например **Flat**. Сохраните его как путь возврата к исходной игре.
2. Создайте ещё один профиль, например **VR**, и переключитесь в него. Обычный диалог создаёт чистый профиль; само имя «VR» не устанавливает порт.
3. Выберите в этом профиле **Astra HD r30** и примените состав. **Первый Native Apply один раз применяет рекомендованный preset сборки, в том числе к уже существующему UserSettings.json, если для версии ещё нет сохранённого или валидно унаследованного режима.** Графические настройки могут измениться. После этого центр сохраняет выбор Custom/«рекомендованные» для версии. Следите за результатом одной операции; не запускайте повторную установку параллельно.
4. Убедитесь, что выбран OpenXR runtime вашего шлема, затем запускайте выбранный профиль из центра и проверяйте изображение в своих условиях.

**Для возврата переключитесь в сохранённый профиль Flat.** Его captured-снимок восстанавливает исходные stock DLL, настройки и сохранённое состояние. Прямой flat-пункт installer у этого минимального комплекта отключён: пустая карта не содержит оригинальных DLL для безопасного fallback. Его нельзя заменять ручным удалением файлов.

**Смена профиля восстанавливает сохранённую в нём версию порта.** Публикация r30 не обновляет остальные профили автоматически. Для сравнения новой версии в другом профиле при закрытой игре переключитесь в него, выберите и примените Astra HD r30, затем проверьте результат.

Все установки и переключения выполняются при закрытой игре и менеджерах модов. Профили помогают сохранить состав; они не делают произвольную коллекцию совместимой с VR автоматически.

## Дополнительная проверка native-комплекта

После clean capture можно проверить пути и входы без установки. Из папки **Astra-HD-R30** выполните, подставив свой Steam-путь:

```powershell
pwsh -NoProfile -File .\Install-Selected.ps1 `
  -GamePath "E:\SteamLibrary\steamapps\common\Cyberpunk 2077" `
  -SettingsFile "$env:LOCALAPPDATA\CD Projekt Red\Cyberpunk 2077\UserSettings.json" `
  -CheckOnly
```

`-CheckOnly` не изменяет settings-файл и не заменяет сохранение чистой основы. Прямой installer с явно указанным существующим SettingsFile сохраняет его, но обычный путь через центр затем выполняет описанную однократную инициализацию recommended preset. Это разные стадии; сохранение файла installer само по себе не означает, что первый Native Apply оставит всю графику прежней. Основной профильный порядок установки и возврата описан выше.

## Обновление R29 и обязательные настройки порта

Для распознанного обновления родительской R29 до R30 сохранённый режим Custom и текущий пользовательский JSON наследуются. Если проверенного режима нет, действует описанная выше однократная инициализация recommended preset. Не переносите чужой config и не подменяйте текущие настройки старым preset вручную.

Обязательная настройка `xr_hud_to_second_eye=1` хранится в рецепте сборки и согласуется в фактически используемом `vrport.ini` при установке, Apply/Custom и перед запуском. Custom сохраняет пользовательскую графику и прочие портовые параметры; он не отменяет этот обязательный HUD-флаг. Эта узкая правка не задаёт другие значения PPD, AER или калибровки. Фактический результат для конкретной коллекции проверяется отдельно; возврат из редактора к чёрному composed-миру в Test3 и VR Night City не объявлен исправленным одним HUD-флагом.

## Что не устанавливается этим выпуском

Native-base сохраняет выбранные NVIDIA SR/RR/G **310.9.16.0**, editor archive, обязательные framework и скрипты. **Optional common OptiScaler/NR/MFG не включён и для первого запуска native-основы не требуется.** Отсутствие `shared-package.json` у этой пары штатное. Совместная работа NR+FG будет отдельным этапом; её настройки или горячие клавиши здесь не обещаются.

Полные лицензии и notices находятся рядом с runtime. Границы проверок, открытые артефакты изображения и измеренные сроки — в [STATUS.md](STATUS.md).
