# VR-центр — текущая работа (3.1.7, 16.10.2026)

Нажатие на «Текущий запуск» открывает расширенные настройки фактически активного режима, независимо от последнего просмотренного порта. На главной рядом с тестовыми сохранениями находятся REDmod и NR + MFG. Сохранённые плоские сборки определяются по `kind=flat`, а не только по ID `flat`.

Галочка REDmod задаёт `-modded`; наличие инструмента проверяется отдельно. Сохранённый штатный комплект задаётся через `config.redmodPackage`. При включении или подготовке запуска отсутствующие файлы восстанавливаются из этого комплекта; выключение меняет только флаг и сохраняет инструмент. Исходники хранятся вне профилей. REDmod подготавливает моды через тот же автономный VFS; для общих архивов создаются пустые родительские папки в частном дереве, без копирования архивов.

## Коллекция, порт и сохранения в одном профиле

Выбрать игровой профиль под Cyberpunk → «Коллекция…» → Vortex → установленный профиль → «Подключить». Для первого чтения/импорта Vortex должен быть закрыт. Далее запуск автономный: используется встроенный usvfs, Vortex и MO2 не запускаются. Копия базы читается только по ключам профилей и установленных модов, исходная база не изменяется. Конфликты берутся из подтверждённого deployment либо правил и file overrides; неоднозначный состав не угадывается.

Частные скрипты/настройки коллекции находятся в `data/collection`, архивы — в общей библиотеке `data/shared-collections` как NTFS hardlinks. Смена порта не переключает и не переустанавливает коллекцию. Из старого полного снимка VR-порта берутся его собственные компоненты: общие ArchiveXL/CET/RED4ext и другие моды остаются от выбранной коллекции; текущие UserSettings не заменяются старым пресетом. Подготовленный пакет — производный, исходный каталог/CAS не переписывается. Выбор предпочитаемой версии семейства хранится в `config.preferredPorts`.

«NR + MFG» использует `config.imagePackage`. При выборе VR плоский комплект временно снимается, при возврате в flat восстанавливается вместе с пользовательскими INI. Собственная FG выбранного VR-порта сохраняется в его комплекте. Включение/выключение синхронизирует critical receipt, не сбрасывает NR/FG при запуске. Включённый флаг обозначает подключение файлов, а не доказанный игровой FPS.

На главной в «Текущий запуск» есть «Тестовые сохранения» и «Набор…». Исходные копии и SHA находятся в общей `data/test-save-library`, рабочие копии и выбор — в профильной `data/game-settings/test-saves`. Новый профиль начинает с OFF и всеми наборами в выборе. ON добавляет копии в свободные ManualSave-N; OFF паркует только собственные папки, сохраняя изменения игрока. Чужие сохранения и user.gls не удаляются. При повторном ON возвращаются рабочие копии этого профиля; новый профиль получает чистые исходники. В «Набор…» можно отключать наборы и импортировать распакованную папку с sav.dat. Игру перед изменением сохранений нужно закрыть.

Проверки: `tests/vortex-collection.tests.ps1`, `vortex-read-catalog.tests.js`, `collection-port-install.tests.ps1`, `enhancement-port-lifecycle.tests.ps1`, `test-saves.tests.ps1`; headless UI `--vortex-collection` и `--test-saves`. Это проверки файлового жизненного цикла и UI, не запуск Cyberpunk и не HMD-приёмка.

## Историческое описание интерфейса 2.0

Ниже сохранена история старой версии. Её ограничения Vortex/Purge и номер выпуска не описывают текущий 3.1.6.

Основной ярлык `VR порты` открывает личную библиотеку. Карточка Cyberpunk открывает простой режим; кнопка «Расширенный режим» показывает сетку компонентов. Вкладка VR-ПОРТЫ группирует форки, внутри каждого — список его версий. Основные страницы и состояния повторяют структуру изученного живого DLSS 5 Manager 1.3.4; визуальные ресурсы остаются из его исходников, авторство сохранено.

## Действия
- Карточки компонентов: переключатель, фактическое/ожидаемое состояние, доступность для выбранного порта. Зелёный — установленное/включённое, красный — выключение/ошибка, серый — недоступность отдельного подключения, голубой — изменение до применения.
- В карточках DLSS SR/FG/RR выбирается версия DLL из существующего комплекта. Поддерживается выбор 310.8 и 310.9.1 там, где соответствующий файл действительно есть. Библиотеки проверяются SHA; обновляется контрольная сумма в квитанции запуска. Наличие DLL не доказывает работу генерации в шлеме.
- «Применить изменения: N» применяет выбранные компоненты. «Запустить» запускает установленный комплект. При неприменённом выборе запуск недоступен, чтобы не запустить другую сборку.
- «Vortex» временно убирает/возвращает дополнительные файлы из областей модов; обязательные файлы из квитанции VR-порта сохраняет. Это не переключение профиля в LevelDB Vortex. Повторный Deploy может вернуть дополнительные моды; обновление окна учитывает появившиеся файлы. Журналы/JSON/cache/tmp не убираются. Область сканирования унаследована от Core: archive/pc/mod, r6/scripts, r6/tweaks, red4ext/plugins, CET/mods. Моды вне этих областей этим переключателем не управляются.
- При смене самого порта со сторонним deployment Vortex сохраняется прежняя блокировка до Purge, чтобы установщик не рассогласовал состав. Само включение/выключение дополнительных модов отдельной транзакцией допускается при закрытых Vortex и игре.
- «Добавить VR-порт»: название, версия, ZIP и основа зависимостей. Поддержан ZIP форка CyberpunkVR_Stereo с привычной структурой red4ext/plugins. EXE-инсталляторы и архивы другого формата отклоняются. Импорт добавляет запись в каталог без установки в игру. Нельзя считать структурный импорт проверкой совместимости нового форка.
- Ошибка остаётся над нижними кнопками; подробности раскрываются рядом. Запуск использует WatchStartup существующего запускателя. Ошибки первоначального запуска/быстрое завершение возвращаются пользователю; долгосрочное наблюдение за игрой не включено.

## Проверка и границы

Живой исходный Manager открыт и изучен: библиотека, простой/расширенный режимы, группы карточек, нижние кнопки. Запуск игры/применение в исходном Manager не нажимались. Исходник его Launch молча подавляет исключения; наша версия вместо этого показывает ошибку.

Наши библиотека, простой и расширенный режимы осмотрены в живом окне. SHA выбранной DLL/обновление квитанции, выключение/возврат дополнительного мода при сохранении зависимости, конфликт с изменённым файлом, hold, импорт локального ZIP проверены на отдельных тестовых каталогах. `tests/components.tests.ps1`, прежние backend/snapshot tests.

Игра не запускалась и её файлы не менялись: first-launch hold остаётся обязательным. Полная смена реального порта с комбинированием дополнений/библиотек ещё не прогонялась. Компонентные проверки не заменяют эту интеграционную проверку.

Последняя публикация `releases/2.0`. При наличии открытого экземпляра приложение не запускает второй: нужно закрыть прежнее окно и снова открыть ярлык. Сборка в отдельный каталог позволяет обновлять ярлык без перезаписи DLL открытого приложения. `Build.ps1` всегда создаёт новый каталог. Исходный устаревший README.ru.md относится к интерфейсу 1.0.
